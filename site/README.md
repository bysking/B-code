# B Code 架构讲解站

把 `docs/SHARING.md`(《从零实现一个 Claude Code》)渲染成可交互的讲解站点。

这是一个**独立的子项目** —— 有自己的 `package.json` 与 `tsconfig.json`,不参与主包的构建、
测试和发布。主包仍是零运行时依赖。

## 运行

```bash
cd site
bun install      # 或 npm install
bun run dev      # http://localhost:5173
bun run build    # 产物在 site/dist/
bun run preview  # 预览生产构建
```

## 内容来源

`src/content/knowledge.ts` 是**内容**的唯一真相源(工具清单、阈值、测验题目);
`src/content/journey.ts` 是**叙事结构**的唯一真相源(9 个时刻 + 3 项余论)。

## 叙事结构:跟着一次任务跑一遍

不按「章节」从上到下滑,而是跟着一条真实指令走完全程:

```
「这个项目的测试挂了,帮我看看」
 ├─ 1 你开口        聊天机器人到这就停了,Agent 从此开始动手
 ├─ 2 循环转起来    决定下一步的是模型,不是代码        核心循环
 ├─ 3 换个模型      两家消息格式不一样                后端层
 ├─ 4 它要动手了    模型不是「知道」能读文件            工具系统
 ├─ 5 差点删库      rm -rf 被拦在任何模式之外          权限系统
 ├─ 6 塞不下了      cat 十万行日志,单次吃掉大半窗口      上下文
 ├─ 7 派个人去查    自己读 20 个文件会弄脏主上下文        子 Agent
 ├─ 8 谁说了算      让干活的自己打分,它就说干完了        目标评估器
 └─ 9 跑通了        578 passed, 0 failed              结语
```

每个时刻都是「**发生了什么 → 此刻为什么需要它 → 深入看**」三拍,细节默认收起:
首读约 8,000px,全部展开 16,000px。

左侧常驻**进度轨**(`JourneyRail`)随滚动点亮当前时刻、走过的连线变实;
视口窄于 1400px 时自动隐藏,避免压住正文。

## 核心循环:带边的流程图

§1 的 ASCII 图重建为真正有向图(`src/components/LoopFlowchart.tsx`),节点 `n1..n4`
与边 `e1..e4` 都是独立可寻址的 SVG 元素:

```
n1 ──e1──> n2 ──e2(2.1 要用工具)──> n3 ──e4(回到 1)──┐
              │                                      │
              └──e3(2.2 不用工具)──> n4(结束)        └──> n1
```

每一轮循环都会重放 `e2 → n3 → e4`,所以**同一条边会被反复点亮** —— 这正是
「循环」最该被看见的地方。四种视觉状态:

| 状态 | 表现 |
| --- | --- |
| 当前边 | 蓝色 2.5px + 白色流动虚线(方向感),标签加粗变蓝 |
| 走过的边 | 淡蓝细线,表示轨迹 |
| 未到达 | 灰色细线 |
| 结束节点 | 绿色(优先级高于 active,否则完成态永远不出现) |

点「下一步」时同步更新四处:节点高亮、边高亮、伪代码对应行高亮、历史消息数组追加。
左右方向键可单步。窄屏(≤600px)保持最小 26rem 宽度横向滚动,避免节点文字被压缩到看不清。

## 关于演示的真实性

- **权限模拟器的判定逻辑是照搬源码的**:危险的 9 条正则、`CMD_START` 命令边界规则、
  四档模式、敏感命令跳过分类器且 bypass 也要问 —— 全部与 `src/permissions.ts` 一致。
- **Agent 循环模拟器是脚本化的**:工具名与真实清单一致,但轨迹是预设的,不调用真实模型。
- **auto 模式下的分类器**按「假设通过」处理,因为分类器本身要调模型。
- 页面底部「关于这份材料」里列出了所有补充解释的范围。

## 与原文的差异

原文附录称「583 条测试」,实测 `bun test` 为 **579 条**(51 个文件,578 通过 / 1 失败)。
页面在「关于这份材料」中标注了这处更正,并列出其余已核实的数字。

## 技术栈

Vite + React 18 + TypeScript,动画用 `motion`。无 UI 框架依赖 —— 样式在
`src/styles/global.css`,用 CSS 变量做设计令牌。

## 配色:明亮简约

白色画布 + 发丝级边框 + 单一强调蓝(`#2563eb`),靠留白和层次而非色块区分信息。

组件里**没有任何硬编码色值** —— 全部走 `global.css` 的语义 token,每种语义色都分
「文字 / 边框 / 填充」三档(`--green` / `--green-line` / `--green-bg`),换配色只改一处:

| 用途 | token |
| --- | --- |
| 画布 / 表面 | `--bg` `--bg-subtle` `--bg-inset` |
| 文字层级 | `--text` `--text-dim` `--text-faint` `--text-strong` |
| 强调 | `--accent` `--accent-text` `--accent-line` `--accent-bg` |
| 只读 / 写 / 执行 / 外部 | `--green-*` `--amber-*` `--red-*` `--purple-*` |

改配色后用这条命令复核对比度(标题旁会打印每组的 WCAG 比值):

```bash
# 需先把 dev server 与 headless Chrome 跑起来
bun /tmp/contrast.mjs   # 或复用 README 里的算法自行实现
```

当前全部 12 组前景/背景组合均 **≥ 4.5:1**(WCAG AA)。浅色主题最容易踩的坑是
「浅灰小字」—— `--text-faint` 最初取 `#8b929c` 只有 3.1:1,已调到 `#676f7a`。

## 可访问性

语义化标签、可见焦点、键盘可操作(循环模拟器支持左右方向键单步)、
`prefers-reduced-motion` 全局生效、图标按钮带 `aria-label`、图表有文字等价说明。
